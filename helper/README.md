# 远程协助 —— 协助者端（Helper / Server）

本程序是**协助者端**，运行在协助者（你）的电脑上。它监听端口、接收被协助机器的连接、
对每台已连接机器分配唯一 ID，并提供一个 DOS 命令行面板，便于你远程下发命令、查看回显、
管理日志。

> ⚠️ **本程序仅供合法的远程协助、服务器运维、技术支持使用。严禁用于未授权访问、
> 控制他人计算机或任何非法用途。使用本程序即表示你同意仅在拥有明确授权的机器上部署，
> 并对一切使用行为自行承担法律责任。**

## 一、文件结构

```
helper/
├── go.mod                      # 本端独立 module: remoteassist-helper
├── go.sum
├── main.go                     # 入口：初始化日志 → 启动管理器 → 启动心跳检测(后台) → 启动监听(后台) → 启动控制面板(前台)
├── bot.go                      # BOT 对象：ID/IP/Port/WebSocket连接/心跳丢失计数/终端输出流/专属日志
├── manager.go                  # bots 管理器：bots 列表 + 缓存区列表、botID 分配、上线/下线
├── listener.go                 # TCP 监听 → WebSocket 升级，每个连接(每台机器)一个独立协程
├── heartbeat.go                # 心跳检测：1 周期未收到心跳进缓存区，3 周期未收到销毁下线
├── panel.go                    # 主控制面板：log / bots / exit 等命令解析
├── panel_bot.go                # 内嵌终端（仅非 Windows 或弹窗失败时的降级方式）
├── attachserver.go             # 本地 IPC 服务：终端窗口接入、令牌鉴权、输入输出桥接
├── attach_client.go            # -attach 模式：新 DOS 窗口中运行的专属终端进程
├── attach_window_windows.go    # Windows：cmd /c start 弹出独立终端窗口
├── attach_window_other.go      # 非 Windows 平台：返回不支持，回退内嵌
├── console_windows.go          # Windows 控制台：UTF-8 代码页、VT 输入/输出 raw 模式、窗口尺寸
├── console_other.go            # 非 Windows 平台的空实现
├── e2e_test.go                 # 端到端回归测试
├── protocol/
│   └── message.go              # 与用户端共用的消息协议（JSON，终端字节流用 base64 承载）
└── logx/
    ├── logx.go                 # programlog（程序运行日志）+ botslog（所有连接过的主机记录）
    └── botlog.go               # botlog：每台机器一个专属日志（完整终端录像 + 连接事件）
```

运行时会在当前目录生成 `logs/` 目录：

```
logs/
├── program.log                 # 程序运行日志（正确 + 错误）
├── bots.log                    # 所有连接过的主机，及对应 botlog 文件名
└── botlogs/
    └── <botID>.log             # 每台机器的专属日志（命令 + 回显，心跳不写入）
```

## 二、编译方式

本端是一个独立的 Go module，无需依赖其它目录。

### 前置要求

- Go 1.21+（推荐最新稳定版）

### 编译为 exe（Windows）

在 `helper/` 目录下执行：

```powershell
go build -o helper.exe .
```

即可生成 `helper.exe`。

### 跨平台编译（在 Windows 上编译 Linux 版本）

```powershell
$env:GOOS="linux"; $env:GOARCH="amd64"; go build -o helper . ; $env:GOOS=""; $env:GOARCH=""
```

### 编译时关闭控制台窗口（可选，纯后台运行）

```powershell
go build -ldflags="-H windowsgui" -o helper.exe .
```

> 不推荐日常使用此选项，因为控制面板依赖控制台输入；关闭窗口后将无法输入命令。

## 三、如何让别人连到你的机器（IP 与端口设置）

协助者端**默认监听 `:8080`**（即本机所有网卡的 8080 端口），无需在代码里写死你的 IP。
要让被协助机器连到你，需要做两件事：

### 1. 让你的 8080 端口对被协助机器可达

| 场景 | 做法 |
|------|------|
| 同一局域网（同一 WiFi/内网） | 被协助机器直接填**你的内网 IP**，例如 `192.168.1.100:8080`。先确保你的 Windows 防火墙允许 8080 入站。 |
| 跨公网 | 需要你的机器有公网 IP，或在路由器上做**端口映射**（把路由器公网 IP 的 8080 转发到你内网机器的 8080）。 |
| 没有公网 IP | 用**内网穿透**工具（如 frp、ngrok、zerotier、tailscale）把本地 8080 暴露出去。 |

查看你的内网 IP：

```powershell
ipconfig | Select-String "IPv4"
```

### 2. 把监听端口改成你想要的（可选）

编辑 `main.go`：

```go
const (
    ListenAddr = ":8080"   // ← 改成你想要的端口，例如 ":9000"
    LogDir     = "logs"
)
```

改完重新编译即可。

### 3. 被协助机器侧的配置

被协助机器运行用户端程序（`user.exe`）后，会在同目录生成 `config.json`，
让对方把其中的 `server_addr` 改成你的地址，例如：

```json
{
  "server_addr": "你的公网IP或内网IP:8080",
  "user_id": ""
}
```

保存后重新运行 `user.exe` 即可主动连接到你。

## 四、使用教程

### 启动

双击 `helper.exe`，或在终端运行：

```powershell
.\helper.exe
```

你会看到 `assist> ` 提示符，此时程序已在后台监听 8080 端口。

### 面板命令

输入 `help` 查看全部命令：

```
assist> help

可用命令:
  log -p            查看程序运行日志 (programlog)
  log --bots        查看 botslog（所有连接过的主机）
  log --botlog+ID   查看指定 botID 的专属日志
  bots              查看当前已连接机器的基础信息
  bots -a           查看连接过的全部机器（读 botslog）
  bots -l           查看当前机器的详细信息
  bot [botID]       进入该机器的远程操作面板，执行命令并接收回显
  exit              退出程序
```

### 典型工作流

1. **查看在线机器**：
   ```
   assist> bots
   BOTID        地址
   B4aeddecf    192.168.1.100:54321
   ```

2. **为某台机器打开专属终端窗口**：
   ```
   assist> bot B4aeddecf
   已在新窗口打开 B4aeddecf 的终端，本窗口可继续执行其它命令
   assist>
   ```
   会**弹出一个独立的 DOS 窗口**作为该机器的远程终端，主窗口立即释放、继续可用。
   你可以为不同机器各开一个窗口，同时管理多台主机。

   终端窗口里是一个**真正的终端**（基于 Windows ConPTY），不是一次性命令执行：
   - `cd`、`set` 等状态**跨命令保持**，可以去磁盘任意目录（跨盘用 `d:` 或 `cd /d`）；
   - `diskpart`、`netsh`、`python`、`set /p` 等**交互式程序可直接使用**；
   - **Ctrl+C 透传给远端**（中断远端正在运行的程序），不会关闭窗口；
   - **Ctrl+] 关闭终端窗口**；关闭后远端 shell 继续存活，再次 `bot [ID]` 开窗口仍是原现场；
   - 终端默认从被协助方的**用户主目录**启动；
   - 同一台机器同时只能开一个终端窗口（防止输入抢占）；
   - 机器下线时窗口会提示并等待回车，不会闪退。

3. **查看某台机器的历史操作记录**（botlog 是完整终端录像）：
   ```
   assist> log --botlog+B4aeddecf
   2026-09-11 21:28:14 [SYS] 上线 192.168.1.100:54321
   2026-09-11 21:30:00 [SYS] 终端面板接入
   C:\Users\用户名>whoami
   desktop-xxxx\user
   C:\Users\用户名>_
   2026-09-11 21:35:10 [SYS] 终端面板脱离
   ```

4. **退出程序**：
   ```
   assist> exit
   程序已退出。
   ```

### 心跳与下线机制

- 用户端每 5 秒发一次心跳，只用于保活，**不写入任何日志**。
- 协助者端每 10 秒检测一次：连续 1 个周期没收到 → 机器进入"缓存区"继续等待；
  连续 3 个周期（约 30 秒）没收到 → 自动销毁协程，标记下线。
- 用户端正常退出时会主动发送下线通知，协助者端立即感知。

这些参数在 `protocol/message.go` 中可调：

```go
const (
    HeartbeatInterval = 5 * time.Second   // 用户端心跳间隔
    HeartbeatPeriod   = 10 * time.Second  // 服务端检测周期
    MaxMissed         = 3                 // 允许连续丢失的周期数
)
```

## 六、常见问题

**Q：客户端连不上？**
A：检查 Windows 防火墙是否放行 8080 端口；检查你的 IP 是否对客户端可达（同网段用内网 IP，
跨网用公网 IP / 内网穿透）。

**Q：`bots` 看不到机器？**
A：确认客户端 `config.json` 的 `server_addr` 指向你正确的 IP:端口，且客户端已运行。

**Q：日志在哪？**
A：`helper.exe` 所在目录的 `logs/` 文件夹下。
