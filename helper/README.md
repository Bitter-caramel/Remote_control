# 远程协助 —— 协助者端（Helper / Server）

本程序是**协助者端**，运行在协助者（你）的电脑上。它监听端口、接收被协助机器的连接、
对每台已连接机器分配唯一 ID，并提供一个 DOS 命令行面板，便于你远程下发命令、查看回显、
管理日志。

> ⚠️ **本程序仅供合法的远程协助、服务器运维、技术支持使用。严禁用于未授权访问、
> 控制他人计算机或任何非法用途。使用本程序即表示你同意仅在拥有明确授权的机器上部署，
> 并对一切使用行为自行承担法律责任。**

## 二、编译方式

本端是一个独立的 Go module，入口包在 `cmd/helper`。

### 前置要求

- Go 1.21+（推荐最新稳定版）

### 编译为 exe（Windows）

推荐直接双击仓库根目录的 `scripts/build-helper-windows.bat`（产物在 `bin/helper.exe`）。
手动编译：

```powershell
cd helper
go build -o ..\bin\helper.exe ./cmd/helper
```

### 跨平台编译（在 Windows 上编译 Linux 版本，纯静态无需 gcc）

双击 `scripts/build-helper-linux-amd64.bat`，或手动：

```powershell
$env:GOOS="linux"; $env:GOARCH="amd64"; $env:CGO_ENABLED="0"
go build -o ..\bin\helper_linux_amd64 ./cmd/helper
$env:GOOS=$null; $env:GOARCH=$null; $env:CGO_ENABLED=$null
```

### 编译时关闭控制台窗口（可选，纯后台运行）

```powershell
go build -ldflags="-H windowsgui" -o ..\bin\helper.exe ./cmd/helper
```

> 不推荐日常使用此选项，因为控制面板依赖控制台输入；关闭窗口后将无法输入命令。

## 三、如何让别人连到你的机器（IP 与端口设置）

协助者端**默认监听 `:8080`**（即本机所有网卡的 8080 端口），无需在代码里写死你的 IP。
要让被协助机器连到你，需要做两件事：

### 1. 让你的 8080 端口对被协助机器可达

| 场景 | 做法 |
|------|------|
| 同一局域网（同一 WiFi/内网） | 被协助机器直接填**你的内网 IP**，例如 `192.168.1.100:8080`。先确保你的 Windows 防火墙允许 8080 入站。 |
| 跨公网 | 需要你的机器有公网 IP，或在路由器上做**端口映射**（把路由器公网 IP 的 8080 转发到你内网机器的 8080）。 |
| 没有公网 IP | 用**内网穿透**工具（如 frp、ngrok、zerotier、tailscale）把本地 8080 暴露出去。 |

查看你的内网 IP：

```powershell
ipconfig | Select-String "IPv4"
```

### 2. 把监听端口改成你想要的（可选）

编辑 `main.go`：

```go
const (
    ListenAddr = ":8080"   // ← 改成你想要的端口，例如 ":9000"
    LogDir     = "logs"
)
```

改完重新编译即可。

### 3. 被协助机器侧的配置

被协助机器运行用户端程序（`user.exe`）后，会在同目录生成 `config.json`，
让对方把其中的 `server_addr` 改成你的地址，例如：

```json
{
  "server_addr": "你的公网IP或内网IP:8080",
  "user_id": ""
}
```

保存后重新运行 `user.exe` 即可主动连接到你。

## 四、使用教程

### 启动

双击 `bin\helper.exe`，或在终端运行：

```powershell
.\bin\helper.exe
```

你会看到 `assist> ` 提示符，此时程序已在后台监听 8080 端口。

### 面板命令

输入 `help` 查看全部命令：

```
assist> help

可用命令:
  log -p            查看程序运行日志 (programlog)
  log --bots        查看 botslog（所有连接过的主机）
  log --botlog+ID   查看指定 botID 的专属日志
  bots              查看当前已连接机器的基础信息
  bots -a           查看连接过的全部机器（读 botslog）
  bots -l           查看当前机器的详细信息
  bot [botID]       进入该机器的远程操作面板，执行命令并接收回显
  exit              退出程序
```

### 典型工作流

1. **查看在线机器**：
   ```
   assist> bots
   BOTID        地址
   B4aeddecf    192.168.1.100:54321
   ```

2. **为某台机器打开专属终端窗口**：
   ```
   assist> bot B4aeddecf
   已在新窗口打开 B4aeddecf 的终端，本窗口可继续执行其它命令
   assist>
   ```
   会**弹出一个独立的 DOS 窗口**作为该机器的远程终端，主窗口立即释放、继续可用。
   你可以为不同机器各开一个窗口，同时管理多台主机。

   终端窗口里是一个**真正的终端**（基于 Windows ConPTY），不是一次性命令执行：
   - `cd`、`set` 等状态**跨命令保持**，可以去磁盘任意目录（跨盘用 `d:` 或 `cd /d`）；
   - `diskpart`、`netsh`、`python`、`set /p` 等**交互式程序可直接使用**；
   - **Ctrl+C 透传给远端**（中断远端正在运行的程序），不会关闭窗口；
   - **Ctrl+] 关闭终端窗口**；关闭后远端 shell 继续存活，再次 `bot [ID]` 开窗口仍是原现场；
   - 终端默认从被协助方的**用户主目录**启动；
   - 同一台机器**可以被多个终端同时接入**（多个 DOS 窗口 / 多个浏览器页面混用均可）：
     远端输出广播给所有接入者，任何一方的按键都会生效；多人同时输入会互相干扰；
   - 机器下线时窗口会提示并等待回车，不会闪退。

3. **给 Agent / 自动化脚本使用的 CLI 模式**（主程序保持运行，另开终端执行）：
   ```
   helper.exe -cli list --json
   helper.exe -cli exec B4aeddecf 'ipconfig /all' --json
   ```
   - `list` 返回在线机器（JSON），`exec` 在指定机器执行**一次性命令**并返回输出与退出码；
   - 一次性命令在被控端独立 shell 进程执行，**与交互终端窗口互不干扰**、无目录状态保持；
   - 退出码透传远端命令；本地/协议错误退出码为 2；`--timeout` 默认 120 秒、上限 600 秒；
   - 所有 `-cli exec` 都会写入该 bot 的 botlog（`[AGENT]` 审计行）；
   - 完整的机器对接说明、JSON 契约与安全红线见 **`../Agent/README.md`**。

4. **查看某台机器的历史操作记录**（botlog 是完整终端录像）：
   ```
   assist> log --botlog+B4aeddecf
   2026-09-11 21:28:14 [SYS] 上线 192.168.1.100:54321
   2026-09-11 21:30:00 [SYS] 终端面板接入
   C:\Users\用户名>whoami
   desktop-xxxx\user
   C:\Users\用户名>_
   2026-09-11 21:35:10 [SYS] 终端面板脱离
   2026-09-13 10:02:11 [AGENT] CMD > ipconfig /all
   2026-09-13 10:02:11 [AGENT] OUT < exit=0 ...（输出）
   ```

5. **退出程序**：
   ```
   assist> exit
   程序已退出。
   ```

### 浏览器控制台（WebUI）

除了 DOS 面板，本程序启动后**同时是一个 Web 服务**：在同网段的任意设备（电脑、手机、平板）
用浏览器打开

```
http://<协助者机器的 IP>:8080/
```

就能直接操作，**不需要安装任何客户端**。

> ⚠️ **首次启动会自动创建管理员账号**，并在控制台打印一串**只显示一次**的随机口令：
>
> ```
> ========== 已创建初始管理员账号（口令只显示这一次，请立即保存） ==========
>   账号: admin
>   口令: Xy7kQ2w-pLm9Ab
> ======================================================================
> ```
>
> 忘记口令时的重置办法：停掉程序，删除 `logs/helper.db`（会一并清空账号与审计），
> 下次启动重新生成初始管理员。

- **登录**：打开页面先出现登录框，输入账号 / 口令后进入控制台。
  登录态保存在 `httpOnly` Cookie 里（`SameSite=Strict`），脚本读不到、也不会随第三方站点发送。
- **界面**：仿桌面版 IM 的三栏结构 —— 最左导航栏选功能，第二列是该功能的列表，主区是内容。
  导航栏条目按角色自动显隐，左下角显示当前角色并提供**登出**。
- **终端**：主区是一整块真终端（xterm.js），不是聊天式发送框。第二列列出当前在线机器，
  点开即可操作，按键直接透传到远端 shell，体验与 `bot [ID]` 弹窗完全一致。
- **日志**：可直接查看 programlog / botslog / 每台机器的终端录像，无需去翻 `logs/` 目录。
- **离线可用**：前端（含 xterm.js）全部内嵌在 `helper.exe` 里，不依赖外网 CDN。
- **扩展方式**：前端功能模块通过 `registerPanel()` 自注册，外壳只读注册表，
  新增功能不需要改外壳（见 `internal/webui/assets/js/`）。底部面板同理，用 `UI.dock.register()` 注册标签页。

#### 占用状态与预定（排队）

一台机器**同一时刻只允许一个人输入**，避免多人同时敲键盘互相干扰：

| 你的身份 | 机器空闲 | 机器已被占用 |
|----------|----------|--------------|
| 观察者（角色 1） | 只读旁观，不占用、不排队 | 同左 |
| 普通用户 / 管理员 / 本机 DOS 终端 | 立即成为**占用者**，可输入 | 自动**排队**（FIFO），能看画面但不能输入 |

- **机器列表**里每台机器下方会多一行占用状态，只有四种文本：
  `无人占用` / `张三 占用` / `张三、李四 占用` / `张三 等 3 人占用`；
  后面按需追加灰色的「· 2 人观察中」「· 3 人排队」。同一账号开多个标签页只算一个人。
- 前面的人关闭页面、主动放弃或闲置超时后，**队首自动获得控制权**并弹出提示，无需刷新页面。
- **底部面板**（界面中间底部，仿 VSCode 的 panel，默认收起）自带标签栏，
  当前提供「我的预定」：列出你正在占用 / 排队的机器与位次，可在此**放弃**控制权；
  后续新增功能只需再注册一个标签页。
- **播报**面板记录占用 / 排队 / 释放的历史（内存保存最近 500 条，重启即清空）；
  只有点进该面板才会拉取数据，不做常驻推送。可见范围与机器列表一致，按机器等级过滤。

#### 闲置下线确认

占用者**连续 5 分钟既没有输入、机器也没有输出**时，服务端会在终端上方弹出确认条
「是否下线？」并倒计时 1 分钟：

- 点**是**或倒计时结束 → 释放控制权，自动让位给排队者；
- 点**否** → 重新计 5 分钟。

判定条件是「用户无输入 **且** 机器无输出」，因此装环境、拉依赖、`ping` 这类
长时间没有人工输入但持续刷屏的任务**不会**被误判为闲置。
本机 DOS 终端不参与此机制（它没有应答界面），需要腾出机器时请直接在面板里退出。

#### 角色与权限

账号分三档，**权限以数据库为准，改动即时生效**（改角色 / 改口令 / 停用后，旧会话立刻失效）：

| 角色 | 值 | 能做什么 |
|------|----|----------|
| 观察者 | 1 | 只读。可看列表与日志、可**旁观**终端输出，但不能输入、不能下发命令 |
| 普通用户 | 2 | 可操作其**可见等级范围内**的机器（输入、resize、一次性命令） |
| 管理员 | 3 | 全部权限：用户管理、机器分级、可操作任意机器 |

**机器也有等级**（`bots.min_role`，默认 2）：只有角色值 **≥** 该机器等级的账号才能看到并操作它。
例如把某台机器设为 `min_role=3`，它就只对管理员可见。管理员可在「机器管理」面板里逐台调整等级与备注。

#### 管理员专属功能（导航栏多出的两项）

- **用户管理**：新增账号（口令留空则自动随机生成并在页面上显示一次）、改显示名、改角色、
  重置口令、启用/停用、删除账号；为避免把自己锁在门外，**最后一个可用管理员**不允许被降级/停用/删除。
- **机器管理**：逐台查看机器（在线 / 缓存 / 离线）、调整 `min_role` 可见等级、填写备注。

> ⚠️ **WebUI 与 `/ws` 共用同一个端口**（`/ws` 给用户端连入，其余路径是控制台），
> 站点已启用登录鉴权，但**整条链路仍无 TLS**，口令与 Cookie 在网络上以明文传输。
> 请只在可信网络内使用，切勿把 8080 直接暴露到公网。

### 心跳与下线机制

- 用户端每 5 秒发一次心跳，只用于保活，**不写入任何日志**。
- 协助者端每 10 秒检测一次：连续 1 个周期没收到 → 机器进入"缓存区"继续等待；
  连续 3 个周期（约 30 秒）没收到 → 自动销毁协程，标记下线。
- 用户端正常退出时会主动发送下线通知，协助者端立即感知。

这些参数在 `protocol/message.go` 中可调：

## 六、常见问题

**Q：客户端连不上？**
A：检查 Windows 防火墙是否放行 8080 端口；检查你的 IP 是否对客户端可达（同网段用内网 IP，
跨网用公网 IP / 内网穿透）。

**Q：`bots` 看不到机器？**
A：确认客户端 `config.json` 的 `server_addr` 指向你正确的 IP:端口，且客户端已运行。

**Q：日志在哪？**
A：`helper.exe` 所在目录的 `logs/` 文件夹下。

**Q：浏览器打不开控制台 / 打开了看不到机器？**
A：① 访问的是**本机的 IP**而不是 `127.0.0.1`（除非就在本机）；② 确认启动时打印了
「Web 控制台已就绪」；③ 防火墙需放行 8080 **入站**；④ 列表来自 `/api/bots`，
为空说明此刻确实没有用户端在线；⑤ 若前面有反向代理，需放行 WebSocket 的 `Upgrade` 头。

**Q：控制台要登录吗？初始口令是什么？**
A：**需要登录**。首次启动会自动创建管理员 `admin`，随机口令**只在控制台打印一次**，
请立即保存；之后可在「用户管理」里新增其他账号、改口令。
忘记口令时可停掉程序、删除 `logs/helper.db` 后重启，重新生成初始管理员（会清空已有账号与审计）。

**Q：观察者登录后为什么打字没反应？**
A：观察者（角色 1）是只读身份，终端可以旁观但输入会被服务端丢弃。需要操作权限请联系管理员提升角色。

**Q：某台机器所有账号都看不到？**
A：该机器的可见等级 `min_role` 高于你的角色。只有**管理员**能在「机器管理」里调整它。
