# 远程协助 —— 用户端（User / Client）

本程序是**被协助方**运行在自己电脑上的程序。它会主动连接到协助者的服务器，
并允许协助者在你的电脑上执行命令，用于远程协助、排障、运维。

> 🛑 **安全警示（请务必先读）**：
> 本程序会让协助者获得**与本程序运行身份相同的全部权限**，可以执行任意命令、
> 读写文件、修改系统设置。**仅在你完全信任协助者、且确有远程协助需求时运行。**
> 协助者在你机器上的一切操作，等同于你本人操作。请不要在不信任的网络环境、
> 或向不熟悉的人运行本程序。

## 一、文件结构

```
user/
├── go.mod / go.sum             # 本端独立 module: remoteassist-user
├── cmd/user/main.go            # 薄入口，仅调用 internal/agent.Run()
├── internal/agent/             # 全部业务逻辑（package agent）
│   ├── main.go                 #   读/建 config → 主动连接 → 注册 → 心跳 → 转发终端
│   ├── config.go               #   config.json：server_addr / user_id / name
│   ├── conn.go                 #   建立 WebSocket、注册（上报系统与名称）、断线重连、消息收发
│   ├── sysinfo.go              #   系统信息探测（公共）
│   ├── sysinfo_windows.go      #   Windows：版本号（主.次.构建号）
│   ├── sysinfo_other.go        #   Linux：/etc/os-release + 内核版本；其它平台仅 goos/goarch
│   ├── agentexec.go            #   Agent 一次性命令执行（独立 shell，不碰交互终端）
│   ├── shell.go                #   常驻交互式 shell 管理：惰性启动、退出自动重启、输出泵送
│   ├── shell_windows.go        #   Windows：ConPTY 伪终端（旧系统自动降级为管道 shell）
│   ├── shell_other.go          #   非 Windows 平台的 shell 实现（开发自测用）
│   ├── console_*.go            #   UTF-8 代码页（Windows）/ 空实现
│   └── heartbeat.go            #   周期心跳
└── protocol/
    └── message.go              # 与协助者端共用的消息协议（JSON，字节流用 base64 承载）
```

编译产物统一输出到仓库根目录 `../bin/`；构建脚本在仓库根目录 `scripts/`。

运行时会在**当前工作目录**生成 `config.json`：

```json
{
  "server_addr": "协助者的IP:端口",
  "user_id": "",
  "name": ""
}
```

- `user_id` 在首次连接成功后由协助者端自动分配并写入，之后固定不变；
- `name` 是**本机自定义名称**（如"财务室-电脑"），可随时自行填写，协助端会显示；留空则只显示 botID。

## 二、如何编译

本端是一个独立的 Go module，入口包在 `cmd/user`。

### 前置要求

- Go 1.21+（推荐最新稳定版）

### 编译为 exe（Windows）

推荐双击仓库根目录的 `scripts/build-user-windows.bat`（产物在 `bin/user.exe`）。手动编译：

```powershell
cd user
go build -o ..\bin\user.exe ./cmd/user
```

把 `bin/user.exe` 发给被协助方即可。

### 编译 Linux 版（被控机是 CentOS 等时）

双击 `scripts/build-user-linux-amd64.bat`（纯静态，产物 `bin/user_linux_amd64`）。

### 编译时隐藏控制台窗口（可选，后台静默运行）

```powershell
go build -ldflags="-H windowsgui" -o ..\bin\user.exe ./cmd/user
```

> ⚠️ 隐藏窗口后程序在后台静默运行，被协助方看不到任何界面，也无法通过关窗口退出，
> 只能通过任务管理器结束进程。**请确保被协助方知情并同意。**

### 交叉编译（在非 Windows 机器上编译 Windows exe）

```bash
cd user
GOOS=windows GOARCH=amd64 go build -o user.exe ./cmd/user
```

## 三、如何运行

### 1. 配置协助者地址

把 `user.exe`（Linux 上是 `user_linux_amd64`）放到任意目录，**首次运行**会自动生成 `config.json`，
用记事本打开它，把 `server_addr` 改成协助者告诉你的地址，并可选填写 `name`：

```json
{
  "server_addr": "192.168.1.100:8080",
  "user_id": "",
  "name": "财务室-电脑"
}
```

- 同一局域网：填协助者的**内网 IP**（例如 `192.168.1.100:8080`）
- 跨公网：填协助者的**公网 IP** 或内网穿透地址

### 2. 启动

双击 `user.exe`，或在终端运行：

```powershell
.\user.exe
```

看到 `已连接协助者服务器，等待指令。` 即表示连接成功。
此时协助者端就能在他的面板里看到你的机器并接入终端。

### 远程终端是怎么工作的（重要）

- 协助者接入后，你机器上会启动一个**常驻的 `cmd.exe` 交互式终端**（基于
  Windows ConPTY 伪终端，需要 **Windows 10 1809 / Server 2019 或更新版本**；
  更老的系统会自动降级为管道模式，目录仍可保持，但少数交互式程序不可用）。
- 终端从你的**用户主目录**（`C:\Users\你的用户名`）启动，不是 user.exe 所在目录。
- 这是一个完整终端：协助者可以切换任意盘/目录、设置环境变量、运行交互式程序。
- 你这边不会弹出新窗口，一切操作在协助者的终端里完成。终端会话在连接期间一直存活，
  协助者临时退出面板不会关闭它。

### 3. 退出

- 普通模式：直接关闭窗口，或按 `Ctrl+C`（程序会先通知协助者再退出）。
- 隐藏窗口模式：打开任务管理器，结束 `user.exe` 进程。

断线后程序会自动每 5 秒重连一次。

## 四、权限说明（非常重要）

**本程序的执行权限 = 运行它的 Windows 用户的权限。**

| 你怎么运行 | 协助者获得的权限 |
|-----------|----------------|
| 普通双击运行（当前普通用户） | 只有当前普通用户的权限：能读写你自己的文档、运行普通程序，**不能**改系统设置、不能装驱动、不能改其它用户的数据 |
| **右键 → 以管理员身份运行** | **完整管理员权限**：可以改系统设置、安装软件、修改注册表、访问所有用户文件，甚至关闭安全软件 |

### 原则：最小权限

- **绝大多数远程协助场景，用普通用户运行就够了**（看日志、改配置、跑诊断命令等）。
- **只有在确实需要管理员操作时**（如安装驱动、修改系统服务），才用管理员身份运行，
  且操作完成后立即关闭程序。
- 永远不要为了"省事"而长期以管理员身份后台运行。

## 五、通过 Windows 用户和组圈定权限（进阶安全）

如果你希望进一步**限制协助者能做什么**，最安全的做法是：
**专门创建一个低权限的 Windows 用户账户来运行本程序**，
这样即使协助者执行了危险命令，影响范围也被锁在这个受限账户内。

### 方案 A：创建一个普通受限用户（推荐）

1. **新建本地用户**（PowerShell 以管理员运行）：

   ```powershell
   # 创建一个名为 "assist" 的本地用户，设置密码
   net user assist 你的密码 /add
   ```

2. **把它加入 Users 组（默认就是），并从 Administrators 组移除**：

   ```powershell
   net localgroup Administrators assist /delete
   net localgroup Users assist /add
   ```

3. **用这个受限用户运行 user.exe**：

   按住 `Shift` 右键 `user.exe` → **以其他用户身份运行** → 输入 `assist` 账户名和密码。

   或命令行：

   ```powershell
   runas /user:assist "C:\path\to\user.exe"
   ```

   这样协助者只能操作 `assist` 用户能访问的资源，碰不到你的管理员账户和系统关键设置。

### 方案 B：用 NTFS 权限限制文件访问范围

如果你希望协助者**只能访问某个特定文件夹**（例如只让他看 `D:\work`），
可以用 NTFS 权限把 `assist` 用户锁在该目录外：

1. 确保 `assist` 用户对系统盘 `C:\` 只有"读取和执行"权限（默认如此）。
2. 对你想**禁止访问**的文件夹，右键 → 属性 → 安全 → 编辑 → 添加 `assist` →
   勾选"拒绝"列的"读取和执行 / 列出文件夹内容"。

   或命令行（以管理员运行）：

   ```powershell
   # 拒绝 assist 用户访问 C:\Users\你的用户名\Documents
   icacls "C:\Users\你的用户名\Documents" /deny assist:(OI)(CI)RX
   ```

3. 对你想**允许访问**的文件夹，授予 `assist` 读写权限：

   ```powershell
   icacls "D:\work" /grant assist:(OI)(CI)F
   ```

> 注意：NTFS 的"拒绝"权限优先于"允许"。用 `assist` 账户运行程序时，
> 协助者就无法读取被拒绝的文件夹内容。

### 方案 C：用组策略限制可执行程序（白名单）

如果你希望协助者**只能运行指定的几个程序**（如 `cmd.exe`、`notepad.exe`），
可以用 Windows 软件限制策略（SRP）或 AppLocker：

1. 打开"本地组策略编辑器"（`gpedit.msc`，仅专业版/企业版）。
2. 路径：**计算机配置 → Windows 设置 → 安全设置 → 软件限制策略**。
3. 右键 → **创建软件限制策略** → 在"强制"里选择"除本地管理员以外的所有用户"。
4. 在"指定的文件类型"里确保包含 `.exe`、`.bat`、`.cmd`、`.ps1`。
5. 在"安全级别"里把"不允许的"设为默认，然后在"其他规则"里**新建路径规则**，
   把你允许运行的程序路径加入（如 `C:\Windows\System32\cmd.exe` 设为"不受限的"）。

   > 这样 `assist` 用户就只能运行你白名单里的程序，即使协助者下发了危险命令也无法执行。

### 方案 D：沙箱 / 虚拟机（最安全）

如果协助操作涉及不可信内容，最稳妥的方式是在**虚拟机或沙箱**里运行 `user.exe`：

- Windows 自带"沙盒"（`Windows Sandbox`，专业版可选功能）：每次运行都是干净环境，
  关闭后所有改动自动丢弃。
- 或用 Hyper-V / VMware 建一台专用虚拟机。

## 六、网络安全声明

1. **知情与同意**：仅在你明确知情并同意的情况下运行本程序。协助者的每一次操作都相当于
   你本人在操作，请确保你完全信任协助者。

2. **最小权限原则**：用能完成任务的最低权限运行（普通用户优先）。参见上文"权限说明"
   和"Windows 用户和组圈定权限"章节。

3. **网络环境**：本程序以明文（WebSocket）传输命令与回显。建议仅在受信任的局域网使用，
   或在外层使用 VPN / 加密隧道。不要在公共 WiFi 等不可信网络上运行。

4. **及时终止**：协助结束后，请立即关闭 `user.exe`（任务管理器结束进程），不要长期后台运行。

5. **审查与留痕**：协助者端会记录所有执行过的命令和回显。你有权要求协助者提供操作日志，
   或在协助结束后让其清除相关日志。

6. **合法使用**：本程序仅限合法的远程协助用途。不得用于任何违法活动。
   使用者须自行遵守当地法律法规。

## 七、常见问题

**Q：运行后一闪而过 / 连不上？**
A：用命令行运行 `.\user.exe` 看报错；检查 `config.json` 里的 `server_addr` 是否正确，
以及你的网络是否能访问协助者的地址（可用 `Test-NetConnection IP -Port 8080` 测试）。

**Q：协助者说能看到我但执行命令没反应？**
A：检查你的防火墙是否拦截了出站连接，或协助者端的服务是否正常运行。

**Q：怎么彻底卸载？**
A：关闭 `user.exe` 进程，删除 `user.exe` 和 `config.json` 即可，本程序不写注册表、
不装服务、不留后门。
