# 新增 Web 控制台功能插件（后端）

控制台后端采用「每功能一个子包 + init 自注册 + 集中导入清单」的插件式架构。
新增一个后端功能（如：投放文件、拍桌面、远程执行器……）按本指南操作，
不需要改 `server.go` 的任何路由代码。

## 架构总览

```
helper/internal/webui/
├── server.go          # Register：注入依赖 + 挂载内置路由 + feat.MountAll 挂载插件
├── features.go        # ★ 插件导入清单：新增功能在这里加一行空白导入
├── feat/              # 注册表与共享工具（被 features/* 和 webui 共同引用）
│   ├── feat.go        #   Deps、Manifest、RegisterFeature、MountAll
│   └── httpkit.go     #   WriteJSON / WriteError / DecodeBody / Deps.Audit
└── features/          # ★ 每个功能一个独立子包（当前：file）
    └── file/          #   样板功能：文件传输（照抄它的结构即可）
```

为什么注册表要放在 `feat/` 子包而不是 `webui` 里：
功能子包在 `init()` 里调用 `feat.RegisterFeature`，而 `webui` 要空白导入功能子包来触发
`init()` —— 若注册表定义在 `webui`，会形成 `webui → features/x → webui` 的导入环。
`feat` 谁都不依赖，两边都引它，天然无环。

## 新增功能的四步（给 Agent / 人看）

以新增「远程执行器」为例。

### 1. 建包

创建 `helper/internal/webui/features/executor/` 目录，放本功能的全部代码。
建议拆成两个文件（可多可少，保持一个包即可）：

- `feature.go`：`init()` + 元信息 + 挂载函数；
- `handlers.go`：本功能的 HTTP handler（普通函数，第一个参数收 `feat.Deps`）。

### 2. 写 feature.go（照抄模板）

```go
// Package executor 远程执行器功能插件。
// 注册：init() 调 feat.RegisterFeature；webui/features.go 空白导入本包。
package executor

import (
	"net/http"

	"remoteassist-helper/internal/webui/feat"
)

func init() {
	feat.RegisterFeature(feat.Manifest{
		ID:    "executor",              // 全局唯一，建议与包名一致
		Name:  "远程执行器",              // 展示名
		Layer: "L2",                    // L0 内核 / L1 基础 / L2 具体 / L3 用户扩展
		Order: 30,                      // 挂载顺序，小的先挂
		Mount: mount,
	})
}

// mount 挂载本功能的路由（必须显式带鉴权中间件，禁止裸注册）
func mount(d feat.Deps, mux *http.ServeMux) {
	mux.Handle("POST /api/bots/{id}/executor",
		d.Auth.RequireAuth(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			handleRun(d, w, r)
		})))
}
```

### 3. 写 handlers.go

handler 一律是普通函数，第一参数收 `feat.Deps`，从里面取依赖：

| 依赖 | 用途 |
| --- | --- |
| `d.M`    | 机器管理（`d.M.Get(botID)` 取在线 BOT、`RegisterFile` 等） |
| `d.St`   | 数据库（机器等级 `MinRoleOf`、审计 `Audit` 等） |
| `d.Auth` | 鉴权中间件 / `RequireAdmin` |
| `d.Prog` | 程序日志 |

约定：

- 身份：`id, _ := auth.FromContext(r.Context())`，`id.CanOperate()` 判断是否可操作
  （观察者只读），`id.IsAdmin()` 判断管理员；
- 权限：观察者禁止一切写操作；机器级门槛用 `id.Role < d.St.MinRoleOf(botID)` 拦截；
- 输出：`feat.WriteJSON(w, v)` / `feat.WriteError(w, code, msg)`；
- JSON 请求体：`feat.DecodeBody(w, r, &in)`（自动限 4KB）；
- 审计：操作完成/失败时 `d.Audit(id, r, store.ActionXxx, target, detail)`，
  动作常量先在 `helper/internal/store/audit.go` 补一个；
- 新依赖不要乱加：确实需要才在 `feat.Deps` 里加字段（只增不改）。

### 4. 注册进清单

在 `helper/internal/webui/features.go` 的 import 块加一行：

```go
import (
	_ "remoteassist-helper/internal/webui/features/file"
	_ "remoteassist-helper/internal/webui/features/executor" // 新增
)
```

完成。`webui.Register` 启动时会自动挂载，路由即生效。

## 验证

```powershell
cd helper
go build ./...    # 两端编译通过
go vet ./...      # 静态检查
go test ./...     # 单测不回归
```

启动后浏览器打开控制台，确认新功能路由可用、权限拦截生效、审计里有记录。

## 前后端对应

每个后端功能通常配一个前端工具（可选）：在
`helper/internal/webui/assets/js/tool-<id>.js` 里用 `UI.console.registerTool({...})`
注册，控制台面板（每用户每 bot）会自动按机器类型展示。
前端工具的注册模式见 `assets/js/tool-file.js`。
